# 测试驱动修复流程

修复代码问题时按此 workflow 执行:

1. **先跑测试看失败**:`run_tests(dir=仓库路径)`,记下失败的测试名和断言信息
2. **读失败的测试代码**:测试的期望行为就是需求规格,比 issue 描述更精确
3. **定位被测代码**:用 `read_file` 读实现,对照测试期望找差异
4. **最小修改**:只改产生 bug 的位置,不重构、不改测试文件、不动无关代码
5. **重跑测试验证**:必须看到 exit_code=0 才算完成;若仍失败,读新的失败信息回到第 3 步

注意事项:
- 断言 `assert add(2, 3) == 5` 失败给出 `got -1` 之类信息时,直接反推实现错误(如 `-` 写成 `+`)
- 修改文件用 write_file 写完整文件内容,不要只写片段
- 连续 2 次同样的修改仍失败,换思路:重新读测试,检查是否改错了函数
